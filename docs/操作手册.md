# 操作手册

本手册说明 **网页版** 和 **桌面版** 怎么装、怎么开、怎么配密钥，以及当前支持哪些操作系统。两种形态用的是同一套中继控制台和 `/v1` 接口，差别只在启动方式。

截图见仓库根目录 [image.png](../image.png)（实验室探测页）。

## 支持的操作系统

| 形态 | 操作系统 | 架构 | 状态 |
| --- | --- | --- | --- |
| 桌面版（`API for Cursor.exe` / setup / zip） | Windows 10、Windows 11 | 64 位 (x64) | **官方支持** |
| 网页版（`npm run dev`，浏览器打开控制台） | Windows 10、Windows 11 | 64 位 (x64) | **官方支持**，需本机安装 Node.js 22 |
| 桌面版 | macOS、Linux、Windows ARM、32 位 Windows | — | **不提供安装包** |
| 网页版 | macOS、Linux | — | **未作为发布目标维护**；源码虽是 Node + Vite，本仓库只按 Windows 验证 |

还需要：

- 能访问 Cursor 云端 API（默认 `https://api.cursor.com`）
- 一份 Cursor 用户 API Key（Dashboard → Integrations）
- 桌面版无需再装 Node（安装包自带 `node.exe`）
- 网页版必须自行安装 [Node.js 22 x64](https://nodejs.org/)

## 两种形态对比

| | 网页版 | 桌面版 |
| --- | --- | --- |
| 怎么开 | 仓库里 `npm run dev`，再用浏览器 | 双击 exe，或 `npm run desktop` |
| 控制台地址 | 默认 http://127.0.0.1:5173 | 内嵌窗口，同样是本机 5173 |
| API 基址 | 与控制台同一端口：`http://127.0.0.1:5173/v1` | 相同 |
| SDK 桥 | 默认 `http://127.0.0.1:8792/sdk`，Vite 自动拉起 | 相同 |
| 数据目录 | 项目下的 `.wrangler/`（本地 D1） | `%APPDATA%\api-for-cursor\` |
| 适合谁 | 改代码、调试 | 日常使用、发给同事 |

侧栏底部的 **工作端口** 选的是中转 Key。对话、实验室、外部客户端都应走这个 Key。

## 网页版

### 1. 准备

1. 安装 Windows 64 位 Node.js 22。
2. 克隆或解压源码到本机，例如 `D:\project\composer-api-windows`。
3. 不要从别的机器拷 `.dev.vars` 或 `.wrangler`（里面有密钥）。

### 2. 第一次

在仓库根目录打开终端：

```bat
npm install
npm run db:migrate:local
npm run dev
```

浏览器访问：

```txt
http://127.0.0.1:5173
```

首次请求会把加密密钥写入本地 D1，之后不要轮换。不必准备 `.dev.vars`。若仍有旧文件，第一次启动会导入 `ENCRYPTION_KEY`，随后可以删掉。

可选：环境变量 `CONSOLE_PASSWORD` 给控制台设第一道密码，之后在 **系统 → 设置** 修改。

### 3. 之后每次

```bat
npm run dev
```

再打开 http://127.0.0.1:5173 。`npm run dev` 会同时启动 SDK 桥。若要单独跑桥：

```bat
npm run sdk:opencode-bridge
```

只开 Electron 窗口、仍用源码目录（不是安装包）：

```bat
npm run desktop
```

### 4. 改端口

**系统 → 设置** 里可改中转服务监听地址和 SDK 桥地址。改完后重启 `npm run dev`。外部客户端的 base URL 要跟着改。

## 桌面版

### 1. 拿到安装包

发行包在 `dist-win/`（自己打包则执行 `npm run dist:win`）：

| 文件 | 用途 |
| --- | --- |
| `API for Cursor-0.1.1-setup.exe` | 安装到当前用户，开始菜单有快捷方式 |
| `API for Cursor-0.1.1-win.zip` | 便携：解压后运行文件夹里的 `API for Cursor.exe` |
| `win-unpacked\API for Cursor.exe` | 开发机未压缩目录，可直接双击 |

不要用旧的 `*-portable.exe`（会静默解压到临时目录，看起来像卡死）。

### 2. 启动

1. 双击 `API for Cursor.exe`。
2. 未签名时 Windows SmartScreen 可能提示，选「仍要运行」。
3. 会拉起本机 Vite + Worker + SDK 桥，并打开控制台窗口。第一次可能要几十秒。
4. 完全退出后再开，否则会沿用旧进程。

配置和 D1 在 `%APPDATA%\api-for-cursor\`，和安装目录分开，更新 exe 后密钥还在。

启动异常时：

- 环境变量 `STATION_DEBUG=1` 再开一次
- 看 `%APPDATA%\api-for-cursor\station.log`

### 3. 卸载 / 便携版清理

- 安装版：用系统「应用和功能」卸载；用户数据仍在 `%APPDATA%\api-for-cursor\`，要清密钥再手动删这个目录。
- 便携版：删解压文件夹即可；数据同样在 `%APPDATA%`。

## 控制台操作（网页版、桌面版相同）

### 准备 Cursor Token

1. 打开 [Cursor Dashboard](https://cursor.com/dashboard) → Integrations，创建 API Key。
2. 控制台 **密钥 → Cursor Token**，粘贴保存。
3. 不要把 Key 写进 Git 或发给别人。

### 准备中转 Key（工作端口）

1. **密钥 → 中转 Key**，新建一把 `sk-...`。
2. 侧栏底部 **工作端口** 选中这把 Key。对话和实验室都走它。
3. OpenCode、Codex、curl、SDK 的 Bearer 也用这把 `sk-...`。

### 对话

**使用 → 对话**，选模型后发消息。走当前工作端口和 `/v1/chat/completions`。

### 实验室（探测）

**使用 → 实验室**：

1. 确认工作端口已选。
2. 提示词默认类似 `Reply with the single word pong.`，可改。
3. 设并发数，勾选要测的模型（可全选）。
4. 点 **探测所选**。结果表给出状态、HTTP 码、耗时和回复摘要。
5. 需要可 **停止** 或 **重新加载模型**。

探测实际请求 `/v1/chat/completions`，用来确认中继和 Cursor 账号是否通。

### 设置与日志

- **系统 → 设置**：监听地址、控制台密码、SDK 桥。
- **系统 → 访问日志**：`/v1` 和管理接口的请求记录。

### 给外部客户端用

默认（未改设置时）：

```txt
http://127.0.0.1:5173/v1
```

```bash
curl http://127.0.0.1:5173/v1/chat/completions \
  -H "Authorization: Bearer sk-你的中转Key" \
  -H "Content-Type: application/json" \
  -d "{\"model\":\"composer-2.5\",\"messages\":[{\"role\":\"user\",\"content\":\"Hello\"}]}"
```

接口列表、限制项见 [README.md](../README.md)。

## 常见问题

**实验室全是失败 / HTTP 500**  
先看 Cursor Token 是否有效、工作端口是否选了已启用的中转 Key、本机能否访问 Cursor API。SDK 桥默认应在 `127.0.0.1:8792`。

**端口被占用**  
5173 或 8792 被别的进程占用时，到设置里改监听地址，或结束占用进程后重启网页版 / 桌面版。

**桌面版窗口不出现**  
看 `station.log`。确认没有另一个实例还在跑。

**网页版和桌面版数据不互通**  
网页版数据在项目 `.wrangler/`，桌面安装包数据在 `%APPDATA%\api-for-cursor\`，这是两套库。

**打包说明**  
见 [WINDOWS.md](../WINDOWS.md)。
